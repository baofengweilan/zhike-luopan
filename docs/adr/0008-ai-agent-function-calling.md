# 0008 - AI 助手 Agent 化：function-calling + 分级确认 + 无学期代建

日期：2026-10-02。用户试用 AI 助手后提出：1) 未创建学期时无法对话，应不创建也可用；2) 快捷建议应更智能，AI 应具备替用户执行操作的 Agent 能力。经拷问流程（两轮）敲定如下。

## 决策

### 1. 定位升级：从「给建议」到「能执行操作的 Agent」

AI 助手不再只是问答 + 建议跳转，而是能替用户实际执行小程序内操作的 Agent（调课、建提醒、建学期、生成课表等）。这是用户 2026-10-02 明确拍板的核心方向（Q2 = C 档）。

### 2. 执行分级确认（用户选 C）

- **只读操作**（查课表/查放假/查教材）→ 直接回答，不弹确认
- **影响数据的操作**（调课/删课/改学期/设提醒）→ 弹**确认卡片**（列出 AI 拟执行的动作与参数 → 用户点「执行」才动手）
- **无风险操作**（查信息、建提醒等低风险项）→ 直接执行

理由：保留 Agent 办事的爽感，危险操作前设闸；演示时呈现「提出方案 → 请求授权 → 执行反馈」完整闭环，标准 Agent 交互范式。

### 3. 无学期时 AI 代建（用户选 B）

无学期时 AI 可正常对话。用户说"帮我建学期"时，AI 提问 2–3 个关键信息（学期名/起止周）或按常规默认（本学期 20 周），弹确认卡片（"将创建「xxx学期」，a 至 b，共 n 周，执行吗？"）→ 执行 → 引导加课。默认值必须经用户确认，不许 AI 瞎编。

### 4. 大脑：混元 hy3 function-calling，一次规划 + 确认执行（用户选 B）

- 工具清单（首批 6 个）：`query_schedule` / `query_holiday` / `adjust_class` / `create_reminder` / `create_semester` / `generate_schedule`
- 工具定义以 OpenAI 兼容 function-calling 格式交给 hy3（链路见 ADR 0007，已验收）
- 模型决定调用哪个工具与参数 → 后端执行 → 结果回传 → 模型组织自然语言回复
- 多轮 ReAct 规划（想→做→看→再想）**留给赛后**；比赛期一次规划 + 确认执行

### 5. 快捷建议：按本地状态条件渲染三套静态集（用户 2026-10-02 补充拍板）

用户澄清：不做后端动态生成，只做**前端条件渲染**（前端本就知道 semester 是否存在）——三套建议集按状态切换：

- **无学期** → 「帮我建这学期课表」「先设置时令作息」
- **有学期、课表为空** → 「添加一门课」「帮我生成课表」
- **有课表** → 「下节课带什么书」「这周有什么假」

原则：**每条建议必须落到真实存在的功能**（已核查：Excel 导入/导出在拷问中已砍，不存在，故用「帮我生成课表」替代）。语义路由交给 Agent 后，建议话术不再要求精准；按用户数据动态生成个性化建议（后端规则算候选）**留到赛后**，不在本期。

### 6. 交付范围与时间盒（用户选 A + 硬性前提）

- 范围：无学期可用 + function-calling Agent + 确认卡片 + 上述 6 工具 + 演示动线 1 全面升级
- **硬性前提**：先完成 6 条演示动线验证 + 现有成果 commit（重构 + AI 接入落袋），新开发不叠在未验证地基上
- 节奏：10-02 验证 + commit；10-03 ~ 10-10 开发；10-11 ~ 10-14 联调 + 录素材 + 写材料；留 1–2 天 buffer

## 实现要点（开工时展开）

- 后端新增 `/api/ai/agent` 会话式接口：semester_id 可选；组装工具定义调 hy3；执行工具复用现有 service 层（adjuster/notifier/generator），不绕过冲突校验
- 确认卡片数据结构：`{action, params, summary, conflicts?}`，前端渲染卡片而非纯文本；「执行」按钮回传同一 action+params
- 兜底链不变：function-calling 失败 → 降级规则引擎（ADR 0002/0007 链路）
- 所有工具执行走详细中文 debug 日志（长期要求）
