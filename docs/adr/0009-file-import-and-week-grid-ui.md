# 0009 - 文件导入课表（Word/PDF/Excel/图片）+ 课表页周网格改版

日期：2026-10-02。用户提出：课表页要像完美校园一样支持导入文件建课表；AI 助手要能收文件/图片并"看懂办事"；界面改为周网格卡片式。经拷问敲定如下，与 ADR 0008（Agent 化）合并实施。

## 决策

### 1. 架构：一份解析管道，两个入口（用户选 A 合并）

```
解析管道：上传文件 → 类型分发 → 内容提取 → 混元结构化 → 确认卡片 → 入库
入口 A（AI 助手）：发文件给 AI → Agent 调 import_schedule_file 工具 → 确认卡片 → 执行
入口 B（课表页）：「导入课表」按钮 → 选文件 → 同一管道 → 确认卡片 → 执行
```

`import_schedule_file` 追加进 ADR 0008 第 4 条的工具清单（共 7 个工具）。演示主线可串联："发个文件给 AI → 它看懂了 → 请求授权 → 执行"。

### 2. 文件类型与实现路径（用户拍板：四种全支持，路径各异）

| 类型 | 提取 | 结构化 | 本期承诺 |
|---|---|---|---|
| Word | python-docx | 混元 hy3 | 必做保底 |
| Excel | openpyxl | 混元 hy3 | 必做保底 |
| PDF（文本型） | pdfplumber | 混元 hy3 | 必做 |
| 图片 / 扫描 PDF | 混元多模态视觉模型直读 | 同上（视觉模型直接出结构） | 必做，**带验证关卡** |

- 图片路径用混元视觉模型（不走 DeepSeek——其 flash 档纯文本会忽略图片）
- **验证关卡**：10-09 前实测视觉模型对课表截图的识别质量；不达标则切腾讯云 OCR 兜底（通用文字识别 1000 次/月免费，OCR 只出文字丢布局，后接混元理解结构，链路更长故为备选）

### 3. 周次规则近似映射（用户选 B）

真实课表含任意周次集合（"周5无课"、"12-13周,15周"），现模型只有每周/单/双周。导入映射规则：

- 全奇数周 → 单周；全偶数周 → 双周
- 其他 → 按每周处理，课程备注写明"实际为 12-13,15 周"
- 导入完成后 AI 汇报："有 N 门课的周次为特殊规则，已按近似处理并备注"

任意周次列表数据模型（`[12,13,15]`）列入赛后改进。

### 4. 界面改版（用户选 A：本期重做课表页）

- **课表页**：重做为周网格卡片式（完美校园风格，彩色课程卡片 + 周次切换），与导入入口**合并为同一次前端改造**
- **其他页面**：轻度美化（配色、卡片质感），不动结构；首页遵循 ADR 0006 课表即首页
- 配色布局：先按完美校园风格出原型给用户过目再调

### 5. UI 改版新增确认卡片的落点

确认卡片（ADR 0008）是新增交互组件，随本次前端改造一并实现。

## 验证关卡结论（2026-10-03 更新：视觉路径关闭，改为"逐周表格精确提取"）

§2 验证关卡当天实测，两条预设被推翻，路径改道：

1. **视觉模型路径走不通（免费额度内无任何视觉能力）**：
   - 成长计划 AI 资源包二期只覆盖文本模型 `hy3`（官方文档 ai-inspire-plan 明确）；
   - `hunyuan-vision` 等视觉模型名经 ai-proxy 透传实测，上游秒回 429（额度不覆盖，非限流）；
   - 给 `hy3` 发 OpenAI 视觉格式消息（content 数组带 base64 image_url），返回 200 但
     图片被完全忽略（hy3 是纯文本模型）。ai-proxy 无需为图片做任何改造。
   - 备选的腾讯云 OCR 同日搁置：实测发现比 OCR 更强的方案（下条），且 OCR 只出
     扁平文字、丢布局，对"周次归属"这个核心痛点无帮助。
2. **"学校 Word 是纯文本流"判断有误**：`3.docx` 实际含 18 张规整表格（每周一张：
   行 0=周次、行 1=星期表头（后续周省略）、4 条内容行≈1-2/3-4/5-6/7-8 节），
   python-docx 完整可读。此前的 238 条错解析是提取层把表格拍平成文本流所致。
3. **新决策：逐周表格精确提取**（`importer.py: parse_weekly_grid_docx`，经
   `parse_schedule_file` 总入口分发，检测不到该格式自动回退通用文本管道）：
   - 周次/星期/节次槽全部从表格结构确定性读出，LLM 零参与周次归属——不可能再错；
   - LLM 只做一件事：把"物联网传感技术宝教三 607"等粘连单元格拆成课名/教师/教室
     （去重后 <60 条，单次调用 <20s，对比旧管道 71s 整表结构化）；
   - 单元格显式标注权威于表格所在周（"（3-4节）""12-13周,15周"）；节次槽默认按
     1-2/3-4/5-6/7-8 近似（warning 声明，ADR 0009 §3 近似哲学）；
   - "全学期"判断对照文档实际周集合（假期整周缺表不算课缺席）；
   - 归并两级：同名同槽并周 + 教室名截断/空格变体（前缀关系）归并。
   - 3.docx 验收：16 周 248 格 → 47 条精确草稿（旧管道 ~238 条模糊归属）。
4. **遗留**：确认卡片允许用户微调节次（连堂近似"第1节-only"场景）。
5. **（2026-10-03 晚补充，用户拍板）图片路径选腾讯云 OCR**：
   - 备选对比后用户选定 OCR（而非接外部免费视觉 LLM）：留在腾讯云生态、免费额度
     （各产品约 1000 次/月）够演示；
   - 实现（`services/ocr.py` + importer 图片/扫描 PDF 分支）：**表格识别 TableOCR 为主**
     （返回带结构的表格 HTML，非拍平文字），空结果降级通用印刷体 GeneralBasicOCR；
     文本提不出的 PDF 用 pymupdf 渲染前 3 页 PNG 再走 OCR；
   - 密钥：`.env` 的 TENCENT_SECRET_ID/KEY（CAM 控制台 cam/capi 创建）；未配置时 400
     带可执行指引；前端两处文件入口（课表页导入 + AI 助手 📎）已放开 jpg/jpeg/png；
   - 视觉 LLM 直读（GLM-4V-Flash 类免费档）留作升级选项：若 OCR 精度不够或想演示
     "模型直读图片"，后端加三个 AI_VISION_* 配置即可接入（消息格式已用探针验证）。
